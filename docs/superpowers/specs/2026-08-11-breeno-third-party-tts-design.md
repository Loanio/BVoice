# BreenoTTSHook 第三方 TTS 设计规格

## 目标与范围

构建一个基于 Yuki Hook API 的 LSPosed 模块，为 Android 15 / ColorOS 15 上的小布助手 `com.heytap.speechassist` 替换所有进入同一 TTS 组件的播报。首个稳定目标版本为小布助手 11.8.3，其他版本通过保守的特征探测提供实验兼容。

第三方服务默认为 `http://47.111.184.220:5000/`，接口遵循 GPT-SoVITS-Inference 文档：`POST /tts` 用于合成，`GET /character_list` 用于获取角色及情感。用户可在 BreenoTTSHook 模块 APP 和注入的小布设置页中编辑全部配置，两处使用同一份跨进程数据。

## 成功标准

- LSPosed 能识别、启用并将模块作用于小布助手。
- 小布助手 11.8.3 的 TTS 入口能够被精确识别；不确定的版本不得猜测 Hook。
- 所有进入目标 TTS 组件的文本均可交给第三方服务合成。
- 优先复用小布原播放器的音频焦点、停止、打断及完成回调。
- 无法安全使用原播放器时可降级至模块 AudioTrack 播放器。
- 模块 APP 和小布设置页均能完整编辑同一份配置并热更新。
- 角色和情感可从服务动态获取，并支持缓存及手动输入。
- 第三方请求失败时是否回退原版 TTS 由用户开关控制；严格调试模式不得静默回退。
- 自动化测试覆盖配置、请求、WAV 解析、请求代际、回退及跨进程存储的关键行为。
- 交付可安装 APK、测试结果及 LSPosed 启用和诊断说明。

## 非目标

- 不替换 ASR、NLU、唤醒或普通网络请求。
- 不保证未经验证的小布未来版本自动兼容。
- 不在模块中运行 GPT-SoVITS 模型。
- 不默认收集或持久化完整合成文本。
- 不在第三方音频已经开始播放后重播整句原版 TTS。

## 总体架构

```text
小布 TTS 请求
  -> VersionProfile 选择精确或候选 Hook 描述
  -> TtsRequestInterceptor 提取文本、请求身份和回调
  -> GptSovitsClient 调用第三方服务
  -> WavStreamDecoder 解析完整或连续 WAV
  -> AudioNormalizer 统一为播放器接受的 PCM/Opus/文件
  -> OriginalPlayerAdapter
       -> 小布原播放器（优先）
       -> ModuleAudioTrackSink（兼容降级）
  -> 原完成、错误和取消回调
```

模块按职责拆分为 Hook 入口、版本描述、配置桥、服务客户端、音频解析、播放适配、设置界面和诊断八个边界。Hook 类不包含 HTTP、WAV 解析或 UI 逻辑。

## Hook 兼容策略

### 稳定版本

11.8.3 使用经过 APK或设备验证的精确类名、方法名、参数表和回调形状。版本描述至少包含目标包、版本范围、TTS 请求入口、文本参数位置、请求标识来源、停止方法、播放入口及完成/错误回调。

### 实验版本

其他版本只在候选类、参数类型、返回类型和必要成员全部匹配时启用。探测失败或结果不唯一时保持原版 TTS，不执行模糊 Hook。模块设置页显示命中的版本描述和能力状态。

### 接入优先级

1. 在 TTS 组件入口拦截请求，并将标准化音频送回小布播放入口。
2. 仅当业务入口不存在且私有协议已经验证时，才启用版本专属 WebSocket 协议适配。
3. 不采用全局 OkHttp Hook 或音频 Sink 字节替换，避免影响 ASR 和其他网络链路。

## 请求生命周期

每次合成创建单调递增的 generation ID，并按以下状态机运行：

```text
IDLE -> REQUESTING -> BUFFERING -> PLAYING -> COMPLETED
                    \-> FAILED
REQUESTING|BUFFERING|PLAYING -> STOPPING -> CANCELLED
```

新请求会取消旧 HTTP 调用、停止旧播放器、清空队列并增加 generation ID。网络回调、解码数据和播放器回调都必须校验 generation ID；旧代际数据直接丢弃。完成、错误或取消终态只能提交一次。

原始 TTS 调用参数保留到第一个有效音频块成功提交给播放器之后。若在此之前失败且回退开关开启，则恢复原调用；音频开始后失败不得重播原版整句。

## 第三方 API 兼容层

### 合成请求

使用 `POST {baseUrl}/tts` 发送 JSON。字段包括 `text`、`character`、`emotion`、`text_language`、`format`、`top_k`、`top_p`、`temperature`、`batch_size`、`speed`、`save_temp` 和 `stream`。

默认请求 WAV 和流式传输。客户端限制文本长度、响应体、重定向次数、连接超时、读取超时并支持协程取消。

### 角色列表

使用 `GET {baseUrl}/character_list` 获取 `Map<String, List<String>>`。成功结果保存时间戳缓存；失败时显示缓存并保留手动角色/情感输入。手动值不会被刷新覆盖。

### URL 规则

基础地址必须使用 `http://` 或 `https://`，保存时统一尾部 `/`。默认明文 HTTP 仅用于用户指定主机，两个设置入口持续显示传输未加密提醒。

## 音频解析与播放

`WavStreamDecoder` 支持单个完整 WAV、一个 WAV 被任意 HTTP 网络块切分，以及多个按句返回且连续拼接的 RIFF/WAVE 段。

解析器按 RIFF chunk 长度解析，不假定网络边界等于文件边界。它验证 PCM/采样率/位深/声道信息，对不支持或损坏数据返回结构化错误。

播放器接入顺序为：

1. 小布原生 PCM 或音频块入口；
2. 小布原生文件或 URI 入口；
3. 模块 `AudioTrack` 播放器。

仅当验证表明小布入口强制要求 Opus 时添加 PCM 到 Opus 的编码桥。如果只支持文件入口，则每个完整句段写入模块缓存并串行播放。模块播放器申请语音类瞬时音频焦点，并响应小布的停止调用。

## 配置模型

基本设置包含启用状态、基础服务地址、流式传输、连接与读取超时和失败回退。音色设置包含角色、情感、相应手动值、文本语言、语速与格式。高级参数包含 `top_k`、`top_p`、`temperature`、`batch_size` 和 `save_temp`。调试设置包含严格第三方模式、强制模块播放器、日志级别与测试文本。

校验规则包括：有效 HTTP(S) URL、`speed > 0`、`batch_size >= 1`、`top_p` 位于 `0..1`、`temperature > 0` 及合理超时范围。无效配置不得替换上一个有效版本。

## 双入口配置桥

Android 15 下不使用 world-readable preferences。模块提供受限的导出 `ContentProvider` 作为唯一持久化入口：

- 通过 Binder 调用 UID 反查包名，只允许模块自身和 `com.heytap.speechassist`。
- 支持原子批量读取、原子更新和递增 `configVersion`。
- 写入后通过 `ContentResolver.notifyChange()` 通知小布进程。
- 小布进程维护不可变内存快照，TTS 热路径不执行跨进程读取。
- Provider 暂时不可用时继续使用最后有效快照。

模块 APP 使用 Material 3 完整设置页。小布设置 Fragment/Activity 创建时追加“第三方音色”分类并展示全部配置项；优先复用宿主 Preference 组件。宿主框架不兼容时，注入一个设置入口，打开由 Hook 代码构建的完整原生设置面板，而不是删减配置。

两个入口共享配置模型、校验器、角色缓存和配置版本。试听使用当前未保存表单值；只有保存成功才递增配置版本。

## 错误处理与回退

错误按配置、网络、协议、音频、播放器、Hook 六类记录。普通日志只包含阶段、错误码、耗时、格式及 generation ID，不保存完整文本。

回退顺序如下：

1. 原播放器不可用时尝试模块播放器。
2. 两个播放器均失败，或请求/解析在播放前失败时，根据回退开关决定是否恢复原版 TTS。
3. 严格第三方模式下不调用原版 TTS，直接提交结构化错误。
4. 第三方声音开始后发生错误时结束当前请求，不重播整句。

## 测试设计

JVM 单元测试覆盖 URL 和参数校验、JSON 请求、角色列表、缓存、完整/分块/连续 WAV、损坏音频、generation ID、取消、单次终态、播放前后回退差异。网络测试使用本地可控 HTTP 测试服务器，不依赖公网服务。

Robolectric 或 Android 测试覆盖 Provider 调用方检查、原子配置更新、热更新通知、双入口一致性、角色/情感联动及错误提示。

设备验收覆盖模块启用、11.8.3 Hook 命中、普通与长文本、连续提问、播放中打断、网络错误、严格模式、配置即时生效、小布进程重启和模块 APP 被杀后的行为。

## 验证与交付

构建过程必须运行单元测试、Android Lint 和 Debug APK 构建。设备可用时再运行安装、LSPosed 作用域、Hook 日志和真实播报验收。

交付内容包括源码、Debug APK、配置说明、LSPosed 启用步骤、已验证 Hook 能力表和脱敏诊断说明。编译通过、模拟测试通过和真实设备通过必须分别报告，不得互相替代。

## 已知约束

- 当前设计阶段没有可调用的 JADX 上下文；小布原播放器的精确类和方法必须在实施阶段通过目标 APK或连接设备重新验证。
- 默认服务使用明文 HTTP，用户文本可能被网络路径观察；界面必须明确提示。
- 目标目录初始为空且不是 Git 仓库，实施前需初始化 Android/Gradle 工程和版本控制。
